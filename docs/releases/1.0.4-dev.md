# Windows Search Redirector 1.0.4-dev

Pre-release, 2026-10-11. This update adds native Start dismissal without the
closing slide on supported builds, and optional Command Palette positioning.
It remains a development release, not a guarantee across Windows versions.

## Changes

- Hook the newer `StartMenu.dll` animation factory and select Windows'
  `CreateDismissNoAnimation` during an active redirection transaction. Windows
  retains its normal dismissal lifecycle. No forced HWND hiding, private object
  offsets or global animation preference changes are used.
- Add the **Skip Start closing animation during redirection** toggle, enabled
  by default. If the required native symbols are unavailable, normal animated
  dismissal is retained. Outside a redirection transaction, Start is unchanged.
- Add **Command Palette position**: Follow Start horizontally, nine screen
  positions, custom percentages, or the default PowerToys-controlled placement.
- Add monitor selection and a DPI-scaled margin. Follow Start uses the actual
  visible search control via UI Automation, not guessed screen coordinates.
- Keep placement opt-in. It applies only when this mod opens Command Palette,
  not to PowerToys Run, custom launchers or an already-foreground palette.
- Apply late-loaded hooks after initialization and stop the module watcher
  before Windhawk removes hooks. Attempt Explorer's DLL hooks independently.
- Add geometry tests, actual window-placement checks and frame-analysis tools;
  update the English and French READMEs with architecture diagrams.

The mod remains self-contained in one C++ file. `x-cmdpal:` remains the primary
Command Palette activation path.

## Verification And Limits

- 21/21 geometry assertions passed, including all nine grid positions, negative
  monitor origins, DPI-scaled margins and missing-Start fallback.
- The uninterrupted desktop suite passed 11/11 cases: Start-only opening with
  Win, Ctrl+Esc and the taskbar button; clicks without typing; and rapid queries
  through Start and Win+S. Exact text was read back with no input leaked into
  the disposable previous-window sink.
- Six actual placements were verified: top left, top right, center, bottom
  right, custom 50%/25%, and horizontal alignment with Start.
- Frame analysis showed about 200 ms of sliding in the animated control. With
  the native no-animation hook, Start remained stationary until disappearing
  between adjacent frames: 17 ms apart in the typing recording and 34 ms apart
  in the click recording. This is sampling evidence, not a zero-latency claim.
- After restarting StartMenuExperienceHost, Start-only, typing, click and
  animation checks passed again. Explorer was not restarted. A complete Windows
  reboot was not tested.
- The final watcher-shutdown and independent-DLL-attempt edits were compiled
  and installed after the desktop series; that complete series was not rerun
  afterward. The publication build and geometry tests were checked again.
- Launcher/input-readiness observations remained around 220-270 ms. Removing
  the closing slide does not remove launcher activation latency.
- Actual mixed-DPI monitor transfers, every monitor selector, other Windows
  builds and different PowerToys window/card layouts remain unverified.
- Existing limits remain: failure after interception can discard the current
  query; IME/dead-key composition and alternate launchers are not exhaustively
  covered. This release does not claim to resolve every intermittent activation
  or focus issue.

Test environment: Windows 26340.9616 x64, `StartMenu.dll` 2609.14000.0.0,
Windhawk 1.7.3, Command Palette 0.12.12601.0. See the
[investigation report](https://github.com/Fefedu973/Windows-Search-Redirector/blob/v1.0.4-dev/docs/presentation-investigation-2026-10-11.md)
for the native ABI, evidence, test commands and limitations. Raw desktop captures
and unrelated debug logs are not distributed.

## Installation

Use the attached `replace-windows-search.wh.cpp` as the source of your local
Windhawk mod, compile it and enable it. For an existing installation, update
the existing mod rather than creating a second enabled copy.

Positioning defaults to **Default (controlled by PowerToys)**. Choose another
position in the mod settings to enable it. The dismissal toggle can be disabled
independently if necessary.

## Resume En Francais

Cette preversion ajoute un vrai hook de fermeture native sans glissement sur
les builds compatibles du nouveau menu Demarrer. Les captures comparatives le
confirment sur le PC teste, y compris apres redemarrage de son processus.

Command Palette peut maintenant suivre horizontalement Demarrer, se placer
dans les coins ou au centre, ou utiliser des pourcentages personnalises. Le
placement reste desactive par defaut et configurable dans les parametres du mod.

Les tests comptent 21 assertions geometriques, 11 regressions bureau et six
placements reels reussis. Les dernieres corrections du cycle de dechargement ont
ete compilees et installees sans nouvelle serie bureau complete. La suppression
de l'animation ne supprime pas le delai d'ouverture de Command Palette ; les
autres builds Windows et les transferts entre ecrans de DPI differents restent
a valider.
